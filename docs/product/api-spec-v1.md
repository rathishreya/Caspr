Each tool is marked:

## 1. Conventions

### 1.1 Transport
Tools are exposed over Jayant's **MCP interface**, integrated directly from the browser SPA. Still needed from Jayant (`architecture-alignment-v4.md` §11): transport (Streamable HTTP vs SSE), endpoint URL, and how the JWT is passed at session init.

### 1.2 Authentication
**Caspr is the identity provider.** Every request carries a short-lived (≤60 min) RS256 JWT issued by the Caspr backend. Jayant **verifies** it against our JWKS endpoint:

```
GET {AUTH_ORIGIN}/.well-known/jwks.json
```

Claims: `sub` (Caspr user id), `email`, `plan`, `iss`, `aud`, `iat`, `exp`. Jayant never mints tokens. No endpoint is unauthenticated.

### 1.3 Identifiers & time
- `analysis_id`, `section_id`, `file_id`, `anchor_id` — opaque strings, generated by whichever side owns the object. Treat as case-sensitive and ≤128 chars.
- All timestamps are **ISO 8601 UTC** (`2026-08-11T09:30:00Z`).
- Money is **integer cents**, never floats. (Product-side only; not in this contract.)

### 1.4 Errors
Non-2xx responses use one envelope:

```json
{ "code": "analysis_not_found", "message": "No analysis with that id.", "details": null }
```

### 1.5 Rate limiting — required shape
Per-user rate limiting is Jayant's. The client branches its UX on the reason, so the shape matters:

```
HTTP 429
Retry-After: 30
```
```json
{ "reason": "ask_caspr_rate_limited", "retry_after_seconds": 30 }
```

`reason` ∈ `ask_caspr_rate_limited` · `analysis_concurrency_limit` · `account_flagged` · `global_capacity`.

The client shows a soft auto-recovering cooldown for `ask_caspr_rate_limited`, and a **queued** state (never an error) for `analysis_concurrency_limit`.

### 1.6 What must never appear in a response
No model confidence scores, logits, token probabilities, internal model state, prompt text, or model/architecture identifiers. Strip metadata that could reveal model internals (`architecture-alignment-v4.md` §8).

## 2. 🟢 `propose_layout` — instant draft structure

Called the moment the user submits their first prompt. **Perceived latency matters more than completeness**: the client paints a skeleton on submit and populates on arrival. Return a first pass fast, then refine (§2.2).

### Request
```json
{
  "prompt": "The UK electric vehicle market.",
  "depth": "study",
  "client_knowledge": { "icp": "investor", "role": "Strategy Director" }
}
```

| Field | Type | Req | Notes |
|---|---|---|---|
| `prompt` | string | ✓ | Raw user text. |
| `depth` | `"brief" \| "study"` | ✓ | `intelligence` is Phase 2. |
| `client_knowledge` | object | — | Product-side context snapshot; free-form, may be `{}`. |

### Response
```json
{
  "analysis_id": "an_9f2c",
  "revision": 0,
  "sections": [
    { "id": "sec_1", "title": "Executive Summary", "estimated_pages": 2 },
    { "id": "sec_2", "title": "Market Overview and Size", "estimated_pages": 4 }
  ],
  "refinement_questions": [
    { "id": "q_1", "question": "Passenger EVs only, or include commercial fleets?" }
  ]
}
```

- `sections[].id` must be **stable for the life of the analysis** — the client keys UI off it and links executive-summary items to it later.
- `refinement_questions` — the client renders these as the numbered scope list. **5 is the design norm**; fewer is fine.
- `estimated_pages` — positive integer; drives the "~4p" hint.

### 2.2 Live refinement
While the user answers, the Learning Brain may improve the layout. Push updated `DraftLayout` objects with an **incrementing `revision`**. The client replaces its layout when `revision` increases. Sections not yet drafted may be **omitted** — the client renders the remainder as pending skeletons.

## 3. 🟢 `trigger_generation` — commit

Fired by **Generate** at the gate. This is the only call that starts billable work.

### Request
```json
{
  "analysis_id": "an_9f2c",
  "prompt": "The UK electric vehicle market.",
  "depth": "study",
  "clarifications": [
    { "question_id": "q_1", "answer": "Passenger EVs only." }
  ],
  "file_ids": ["file_a1b2"],
  "new_file_id": null,
  "include_user_files": false,
  "output_language": "en",
  "gate": {
    "style": "mbb",
    "output_prefs": {}
  },
  "client_knowledge": { "icp": "investor" }
}
```

| Field | Type | Req | Notes |
|---|---|---|---|
| `clarifications` | array | ✓ | May be empty; unanswered questions are simply absent. |
| `file_ids` | string[] | ✓ | Previously uploaded files to include. |
| `new_file_id` | string \| null | ✓ | File uploaded for this analysis only. |
| `include_user_files` | boolean | ✓ | Include the user's whole Data Room. |
| `output_language` | string | ✓ | ISO 639-1. |
| `gate.style` | enum | ✓ | `mbb` · `big4` · `academic` · `pe` · `scholarly` · `enterprise` |
| `gate.output_prefs` | object | ✓ | 🟢 **firm — see §3.1.** |
| `client_knowledge` | object | ✓ | Sent at generation start, per architecture §7.3. |

### 3.1 🟢 `gate.output_prefs` — the confirmed output configuration

The gate is the **single pre-generation confirmation**: everything affecting cost or output is stated once and committed together. Its shape is now settled (built from Figma `708:63`).

```json
{
  "output_formats": ["pdf", "pptx", "xlsx", "md"],
  "language": "en-GB",
  "style": "pe",
  "template_id": null,
  "data_sources": {
    "file_ids": ["file_a1b2", "file_c3d4"],
    "include_user_files": false,
    "premium_addons": [
      { "id": "bloomberg_terminal", "price_cents": 2500 }
    ]
  }
}
```

| Field | Type | Req | Notes |
|---|---|---|---|
| `output_formats` | string[] | ✓ | Subset of `pdf` · `pptx` · `xlsx` · `md`. Included in the analysis price at launch. |
| `language` | string | ✓ | BCP-47 (`en-GB`), narrower than the top-level ISO-639-1 `output_language`. Prefer this one. |
| `style` | enum | ✓ | Mirrors `gate.style`; kept here so the whole confirmed config travels as one object. |
| `template_id` | string \| null | ✓ | Enterprise custom template. **Phase 2** — always `null` at launch. |
| `data_sources.file_ids` | string[] | ✓ | Files explicitly included via Gate-1 selection. |
| `data_sources.include_user_files` | boolean | ✓ | Include the whole Data Room. |
| `data_sources.premium_addons` | array | ✓ | Opt-in paid sources, each with the price shown to the user **before** commit. Empty at launch unless offered. |

**Premium add-ons are the only line that changes the price at the gate.** The user sees `+$25` next to *Data & sources* before committing; that number must match `sum(premium_addons[].price_cents)`. If you can detect required premium sources before generation, surface them so we can price the gate accurately — otherwise send an empty array and we will not offer them.

**Depth (tier) is confirmed here too**, but travels as the top-level `depth` field, not inside `output_prefs`.

### Response
```json
{ "analysis_id": "an_9f2c", "status": "started", "estimated_minutes": 90 }
```

`estimated_minutes` drives user expectation copy. Brief ≈ 15, Study ≈ 60–120.

## 4. 🟢 `source_stream` — the Theater

Drives the single most important visual in the product. The client has a **working consumer**, so these semantics are load-bearing.

### Events
```json
{ "event": "source_category_activated",  "data": { "category": "Government" } }
{ "event": "source_category_progress",   "data": { "category": "Government", "count": 3 } }
{ "event": "source_category_completed",  "data": { "category": "Government", "total": 7 } }
{ "event": "total_sources_reviewed",     "data": { "count": 1284512 } }
{ "event": "notable_source_found",       "data": { "name": "IMF World Economic Outlook", "category": "Government" } }
{ "event": "cross_reference_detected",   "data": { "category_a": "Government", "category_b": "Academic" } }
{ "event": "stream_complete",            "data": {} }
```

### Rules the client depends on
1. **`total_sources_reviewed.count` must be monotonically non-decreasing** and end on the true total. It renders as a live counter; a decrease reads as a bug.
2. **`notable_source_found.name` is the display string.** The client matches it against the candidate shortlist; a match locks that node red, a non-match joins the list as an organically-found extra.
3. **Partial resolution is expected and correct.** Not every candidate needs to resolve — sources that yield nothing simply never appear. Do not pad the stream to make everything resolve.
4. `cross_reference_detected` is accepted but **not yet visualised** (v1.1).
5. `stream_complete` ends the Learning phase.

## 5. 🟢 Generation events (real-time)

After commit, generation runs asynchronously (a Study can take 1–2 h). Delivered over the WebSocket fan-out (FastAPI → Redis → WS pods).

```json
{ "event": "mode_change",       "data": { "analysis_id": "an_9f2c", "mode": "generating" } }
{ "event": "early_finding",     "data": { "stat": "31%", "label": "of EU charge points are in three countries", "section_id": "sec_2" } }
{ "event": "section_complete",  "data": { "analysis_id": "an_9f2c", "section_id": "sec_2", "title": "Market Overview and Size" } }
{ "event": "analysis_complete", "data": { "analysis_id": "an_9f2c" } }
```

- **`mode_change`** switches the UI from Theater to the generating screen. Emit when Learning + Thinking work is done and writing begins.
- **`early_finding`** — emit as sections finalise; the client controls display cadence. `stat` should be short enough to headline (≤12 chars).
- **`section_complete`** — the client may then fetch that section's content, or it may arrive with the event (§6.3).

## 6. 🟢 Section content — the reading experience

### 6.1 Section object
```json
{
  "id": "sec_2",
  "index": 1,
  "title": "Market Overview and Size",
  "content": "The UK fleet reached 1.3m units⟦sec_2_a1⟧ in 2025, growing 21% year on year⟦sec_2_a2⟧.",
  "anchors": [
    {
      "anchor_id": "sec_2_a1",
      "explanation": "Derived by cross-referencing DfT vehicle licensing statistics with SMMT registrations to Q4 2025.",
      "sources": [
        { "name": "DfT Vehicle Licensing Statistics", "category": "Government", "url": "https://…" }
      ]
    }
  ],
  "chart_data": null
}
```

### 6.2 Red-dot citations — the critical mechanic
- Anchors are **inline trailing markers inside `content`**, immediately after the figure they cite.
- **Marker syntax:** `⟦anchor_id⟧` (U+27E6 / U+27E7). Provisional but centralised in the client — if you prefer a different delimiter, say so once and we change it in one place.
- **Every `anchor_id` in `content` must have a matching entry in `anchors`.** Unmatched markers are dropped by the client.
- **Every anchor carries its explanation and at least one source inline.** Clicking a red dot must require **zero round-trip** — this is a product commitment, not an optimisation.
- `sources[].url` is optional; `name` and `category` are required.

### 6.3 Delivery
Either deliver `content` + `anchors` with `section_complete`, or let the client fetch via `retrieve_analysis`. **Tell us which** — it changes whether the reader streams in or fills on completion.

### 6.4 Charts — raw data, not images
Caspr renders charts client-side so the user can switch type and we can export cleanly. Send data and a suggestion, never a rendered image.

```json
{
  "title": "Charge points by country",
  "suggested_type": "column",
  "fields": [
    { "key": "country", "label": "Country", "role": "dimension" },
    { "key": "points",  "label": "Charge points", "role": "measure" }
  ],
  "rows": [
    { "country": "Netherlands", "points": 152000 },
    { "country": "Germany",     "points": 120000 }
  ]
}
```

- `role` ∈ `dimension` · `measure`. Add `"temporal": true` on a dimension that is a time axis — the client uses it to allow line/area and to **forbid pie**.
- `suggested_type` ∈ `column` · `bar` · `line` · `area` · `pie` · `donut` · `treemap` · `grouped_bar` · `stacked_bar` · `multi_line` · `scatter` · `bubble` · `stat`.
- Row values: string · number · null. Keys must match `fields[].key`.

### 6.5 Executive summary
```json
{
  "insights":  [ { "text": "Charging capacity, not vehicle supply, is the binding constraint.", "section_id": "sec_3" } ],
  "questions": [ { "text": "What would change the conclusion on regulation?", "section_id": "sec_4" } ],
  "infographic": {
    "suggested_template": "headline-led",
    "blocks": [
      { "type": "headline_stat",   "value": "31%", "label": "of capacity in three countries", "emphasis": 1 },
      { "type": "supporting_stat", "value": "$4.2B", "label": "invested in 2025" },
      { "type": "takeaway",        "text": "Concentration is rising; the entry window is narrowing." }
    ]
  }
}
```

- **Every insight and question must carry a valid `section_id`.** The client hyperlinks the summary into the body; a dangling id breaks navigation.
- **Infographic is structured data, not an image URL** — the client renders it into a branded template and lets the user restyle it. Block types: `headline_stat` · `supporting_stat` · `takeaway` · `mini_chart` (`chart_ref`).

`status` ∈ `draft` · `layout_ready` · `generating` · `complete` · `failed`. Sections arrive in `index` order.

## 8. 🟢 `presigned_upload_url`

Browser uploads go **directly to Jayant's S3** — file bytes never transit Caspr's product backend.

### Request
```json
{ "filename": "data-room.pdf", "content_type": "application/pdf", "size_bytes": 2482301 }
```

### Response
```json
{
  "file_id": "file_a1b2",
  "upload_url": "https://…s3…?X-Amz-Signature=…",
  "expires_at": "2026-08-11T09:45:00Z"
}
```

Expiry ≈ 15 minutes. Client constraints already enforced: **max 25 MB**, types PDF · DOC/DOCX · XLS/XLSX · CSV · TXT.

## 9. 🟡 Provisional — do not build first

These consume screens Caspr has not built yet. Direction is settled; field detail will tighten. **Flagged so you don't implement to a shape that moves.**

### 9.1 ~~`gate.output_prefs`~~ → **PROMOTED TO 🟢 FIRM — see §3.1 below**
The Gate screen has now been built, so this shape is settled. Moved into §3.1.

### 9.2 `ask_caspr`
Free-form follow-up Q&A, and the scoped question raised by clicking a red dot. Needed from Jayant: request/response shape, whether it streams, and whether scoped questions reuse the same tool with an `anchor_id`/`section_id` filter. This is the surface your per-user rate limiting targets.

### 9.3 Edit proposals
`visualization-library.md` specifies Caspr proposing **2–3 chart/visual options built from the section's own data**, each with a one-line rationale. Not yet designed as an API. Expect a `propose_visuals(section_id, intent)` shape where intent ∈ Compare · Trend · Composition · Relationship · Geography · Flow.

### 9.4 Outputs / generate-output
Producing PDF/PPTX per version, metered by tier. Needs: who renders (we hold the edited chart/infographic state client-side), and what you return — a file, a URL, or a job id.

### 9.5 Phase 2, not in v1
Intelligence depth · The Signal (`signal_blocks` + `provenance`) · What Changed / Updates · enterprise custom templates · infographic regenerate · output watermarking.
